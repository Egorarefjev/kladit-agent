# Kladit Agent

Linux-агент для мониторинга серверов в Kladit.

Текущая версия предоставляет локальный снимок загрузки CPU, памяти и времени работы сервера. Подключение к control plane пока не реализовано.

## Требования

- Linux с доступными `/proc/stat`, `/proc/meminfo` и `/proc/uptime`.
- Go 1.25 или новее для сборки. Используйте актуальный patch-релиз.

Для сбора метрик root не требуется. Внешних зависимостей нет.

## Сборка

```sh
go build -o bin/kladit-agent ./cmd/kladit-agent
```

## Использование

```sh
./bin/kladit-agent help
./bin/kladit-agent version
./bin/kladit-agent metrics --policy examples/policy.json
```

`metrics` измеряет загрузку CPU за интервал около одной секунды и выводит JSON в stdout. Ошибки направляются в stderr; код завершения — `1` при ошибке сбора и `2` при неверных аргументах.

| Поле | Значение |
| --- | --- |
| `collected_at` | Время завершения сбора, UTC |
| `cpu_usage_percent` | Средняя загрузка всех CPU, 0–100%; idle и iowait исключены |
| `memory_total_bytes` | Общий объём RAM в байтах |
| `memory_available_bytes` | Доступная память по MemAvailable, включая освобождаемый cache |
| `memory_used_bytes` | Общая память минус доступная |
| `uptime_seconds` | Время работы системы в секундах |

Метрики читаются из procfs и не учитывают лимиты контейнера cgroup. Поля снимка собираются последовательно, не атомарно. При уменьшении CPU-счётчиков сбор завершается ошибкой; повторите команду.

## Разработка

```sh
go run ./cmd/kladit-agent metrics --policy examples/policy.json
go test ./...
go vet ./...
```

Сбор метрик поддерживается только на Linux. Справка и версия доступны также на других ОС.

## Локальные разрешения

Команда `metrics` требует явного разрешения `metrics.read` в локальном JSON-файле. Путь по умолчанию: `/etc/kladit-agent/policy.json`. Для разработки можно передать `--policy PATH`.

```json
{"version": 1, "capabilities": {"metrics.read": true}}
```

Отсутствующее разрешение или `false` запрещает операцию. Отсутствующий файл, неизвестные поля и capabilities, повторяющиеся ключи и неверные значения приводят к отказу. Поддерживается только `metrics.read`.

```sh
./bin/kladit-agent policy-check --policy examples/policy.json
```

Проверка подтверждает корректность конфигурации, а не наличие разрешения на метрики. Сбор читает policy перед каждым запуском команды.

Для системной установки файл и родительские каталоги должны принадлежать администратору и быть недоступны для записи пользователю агента. Параметр `--policy` предназначен для локального запуска; сервис использует фиксированный путь. Проверка JSON сама по себе не защищает файл от изменения локальным пользователем или скомпрометированным процессом. Установщик ниже создаёт защищённую policy и использует фиксированный путь в службе.

Привязка к аккаунту и сетевое подключение пока не поддерживаются.

## Установка службы (Linux + systemd)

Текущий установщик настраивает только локальный сбор метрик каждые 30 секунд. JSON записывается в systemd journal. Привязка к аккаунту и отправка метрик в Kladit ещё не реализованы.

Соберите бинарник на Linux той же архитектуры, где будет установлен агент:

```sh
CGO_ENABLED=0 go build -o bin/kladit-agent ./cmd/kladit-agent
sudo sh scripts/install.sh --allow-metrics --check
sudo sh scripts/install.sh --allow-metrics
```

Установка требует root для записи системных файлов. Сбор запускается с временным непривилегированным пользователем systemd, без сетевого доступа. Policy и программа принадлежат root; служба не может их изменять. Повторная установка поверх существующих файлов запрещена, автоматическое обновление пока не поддерживается.

```sh
systemctl status kladit-agent.timer
journalctl -u kladit-agent.service -n 20
sudo systemctl disable --now kladit-agent.timer
sudo systemctl stop kladit-agent.service
```

Чтобы отозвать доступ к метрикам, измените `metrics.read` на `false` в `/etc/kladit-agent/policy.json`. Следующий запуск прочитает новое значение. Уже начавшийся сбор может завершиться; для немедленной остановки используйте команды остановки выше.

### Запуск через SSH

Backend может передать тот же проверенный установочный комплект в закрытый временный каталог сервера и выполнить `sudo -n sh scripts/install.sh --allow-metrics`. Нужны заранее подтверждённый SSH host key и право на установку. Если требуется интерактивный пароль sudo, неинтерактивная установка должна завершиться ошибкой, а не зависнуть в ожидании ввода.

В комплект входят `bin/kladit-agent`, `scripts/` и `packaging/systemd/`. Проверка происхождения комплекта — обязанность вызывающей стороны: установщик не скачивает файлы из сети и не проверяет подписи релиза. Не запускайте непроверенный комплект от root. Удалённый SSH-установщик в backend пока не реализован.

### Удаление

```sh
sudo sh scripts/uninstall.sh --confirm
```

Policy и журнал сохраняются. Если установка завершилась частично, проверьте созданные файлы и статус службы перед повторной попыткой; автоматического rollback нет.
