# План разработки

## Шаг 1 — каркас CLI

Реализовано: Go module, команды help/version, ошибка для неизвестных команд и лишних аргументов, инструкция запуска. Это ещё не работающий серверный агент.

## Следующий шаг — локальные метрики Linux

Добавить команду `metrics`: один снимок CPU/RAM/uptime в JSON, без сети и root. Загрузке CPU потребуется интервал измерения; не выдавать load average за процент загрузки. Проверить на Linux и объяснить значения полей.

## Затем

1. Локальная policy с запретом отсутствующих capabilities и отказом при ошибке конфигурации.
2. Регистрация машины, собственный ключ и отзыв identity; согласовать контракт с backend Kladit.
3. Исходящее защищённое соединение, heartbeat и отправка разрешённых метрик.
4. Установка systemd-сервиса под отдельным непривилегированным пользователем, аудит и удаление.
5. Подписанные релизы и ручное обновление.

Terminal, files, Docker и jobs — отдельные последующие этапы. До реализации изоляции runner удалённое исполнение не добавлять.

## Неизменные ограничения

- Agent не работает от root без конкретной необходимости.
- Backend не может расширить локальную policy.
- Исходящее соединение; входящий порт не нужен.
- Приватный ключ машины не передаётся backend и не попадает в логи.
- Shell не запускается под пользователем, который владеет identity агента.
- Компрометация backend позволяет использовать уже разрешённые операции: policy ограничивает ущерб, а не делает backend доверенным.
