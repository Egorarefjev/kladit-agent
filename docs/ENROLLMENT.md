# Регистрация агента: проект протокола

Статус: проект, не реализованный API. Сетевых команд в CLI пока нет.

Agent устанавливается на Linux-сервер пользователя и инициирует исходящее соединение с Kladit. Входящий порт не требуется. SSH-реквизиты не являются identity агента.

## Предлагаемый процесс

1. Локальная команда enroll генерирует приватный ключ на машине; backend получает только публичный ключ и доказательство владения.
2. Backend создаёт pending enrollment с TTL 10 минут и возвращает pairing code, URL подтверждения и отдельный случайный polling secret.
3. Пользователь входит в свой аккаунт, вводит код и сверяет fingerprint ключа с локальным выводом.
4. Backend атомарно связывает identity с пользователем; повторное подтверждение другим аккаунтом запрещено.
5. Agent получает machine ID и клиентский сертификат. Pending secret уничтожается после завершения. Повтор получения при потере ответа должен требовать доказательство владения тем же ключом.
6. Последующие соединения используют TLS с аутентификацией машины и проверкой её отзыва.

## Backend

Нужны сущности pending_enrollments и agent_identities, связь с существующим владельцем сервера, а также маршруты начала регистрации, подтверждения, получения результата и отзыва. Конкретные пути и миграции согласовать с текущими server/auth-модулями перед реализацией.

Подтверждение требует пользовательской сессии и существующей CSRF-защиты. Короткий pairing code не позволяет получить credentials; polling secret хранится на backend как hash. Ограничить частоту запросов и число pending заявок. Уникальность публичного ключа и однократность подтверждения обеспечиваются БД.

Backend не присылает policy и не расширяет локальные разрешения. Отзыв закрывает активное соединение и запрещает новые. Локальное удаление identity прекращает подключение независимо от backend.

## Критерии завершения

Проверить полный сценарий с реальным backend: регистрация в аккаунте A, отказ аккаунту B, истечение TTL, повторное подтверждение, потерянный ответ, reconnect и revoke. До этих проверок не считать привязку готовой.
